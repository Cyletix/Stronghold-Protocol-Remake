# 故障排查

以本次源码、日志和状态为据，先检查相关入口及已有能力；未找到不等于未实现，别人的结论先作线索。

1. 确定故障发生点与能证伪的假设，对比成功/失败现场。
2. 用最小可逆实验区分假设；有持久副作用时先明确恢复办法。不要同时混改多个无关变量。
3. 取得足以支持修复的证据后实施；跨过原失败临界点再判断结果，日志噪声或“进程还在跑”不能证明根因消失。
4. 验证原故障和受影响行为，报告已确认原因与仍未确认的条件。重复测试只针对新变化或未解决疑点。

## 本项目

- 客户端行为与 `docs/spec/mode-spec.md` 冲突时按 research-evidence 核来源；截图只能证明画面，Web 代码不能覆盖原版事实。
- 渲染/卡顿区分逻辑 tick、绘制帧率、画布尺寸、GPU 与网络快照；单人纯本机路径不要假定经过房间服务器。
- PowerShell 5.1 读无 BOM 中文文件指定 UTF-8；涉及中文的 PS1 保留合适编码。
- 自动维护故障用 supervisor 支持的 Fail/Block/Resume，不新增状态或绕过协议。
