# 持久规则维护

先判断规则是否补充 Agent 缺少的领域知识、是否真正改变决策。保留入口、成功标准、授权/状态/证据边界和必要工具契约；合并重复措辞，删除泛泛要求与无实际消费者的旧规则。

- 安全、权限、状态 schema 等不变量用明确约束；依赖上下文的判断用“何时 → 做什么”，避免互相冲突的绝对禁令。
- 脆弱工具/迁移流程保持具体步骤，普通实现允许合理判断。规则不把用户已授权的例行工作变成额外审批。
- 路由只在项目 AGENTS 维护，方法留在 skill，具体机制/现状留在对应文档，不复制整套规则。
- 范围明确后增量修改，同步真实引用。规则描述完成结果及自然停止条件，避免自我引用式扩充。

修改授权、停止条件或工作流路由后，用代表任务核对普通执行与边界；测试任务只提供实际适用规则，不提示预期答案。多个耦合规则有独立复核价值时可委派子代理；没有子代理不阻止已授权工作。

验证通过后停止扩充；只有新失败证据才增加规则。
