# 变更审查

独立审查默认只读，不提交、发布外部评论或改文件；实施任务中的自检沿用修复授权，修复本次引入的问题。

按当前目标与范围读取完整相关 diff、调用点及测试。只报告本次引入、具有证据且可修复的正确性/安全/性能/契约问题，不用风格偏好、既有问题或投机风险凑数。

按 P0（致命/阻断发布）、P1（立即修）、P2（应修）、P3（较低影响）排序；每项给短标题、精确路径/行、触发场景与后果。无发现就明确说明，未验证的关键边界另列。

## 项目检查点

- 玩法/研究变更对照 `docs/spec/mode-spec.md`、`docs/spec/architecture.md` 和 `docs/research/findings.md`；不把推断写成事实，也不以代码存在代替逐项验收。
- 候选区 UI 核 `tile_achand`、候选与战场实体边界；视觉对照当前用户或任务指定的参考，并检查实际分辨率与交互。
- 清单/生成器核稳定 ID、依据摘要、记录和重建一致性。
- supervisor 工作流中只有 T 文件是执行状态源；归档不参与调度。普通请求不因此被强制导入自动维护。
