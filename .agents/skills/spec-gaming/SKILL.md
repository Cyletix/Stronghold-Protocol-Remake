# 目标与范围校正

以用户明示请求为先，再结合直接目的与上下文；不以推测的“真实意图”覆盖明确要求。

检查当前交付：
- 是否把用户用于纠正行为的话直接塞进产品内容？
- 是否仅因“没有禁止”加入无关功能或扩大改动？
- 是否在纠偏时删掉原有必要行为、制造反向偏差？
- 每个新增说明是否有助于使用、验证或理解成果，还是仅用于表演遵守？

回到原目标，完成必要配套修改，保留已有授权和明确契约。不要把局部反馈推广为无关的全局禁令，也不以缩小交付冒充收敛。

直接交付修正后的结果；目标满足后停止。本 skill 不定义项目架构、权限或任务状态机，单次偏差不自动触发规则系统改造。
