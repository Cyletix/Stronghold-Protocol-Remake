# 文档导航

**想知道接下来做什么，只看[当前推进计划](plan.md)。** 要实施某一项，再沿计划进入对应机制说明和验收条目。

手动与定时续做使用同一条路径：计划选批次 → [机制取证清单](checklists/mechanism-research.md)定位未知项 → [客户端逻辑管线](research/client-logic-pipeline.md)查询/补取证据 → 实现与相关验证 → 回写原清单及计划断点。已解决的历史缺口不重新派工；资料存在、可执行和行为验收分别记录。

| 层级 | 入口 | 维护什么 |
|---|---|---|
| 1 · 方向与顺序 | [推进计划](plan.md) | 当前优先事项、可执行下一步、取证阻塞；不复制逐人勾选 |
| 2 · 全局约定 | [玩法规格](spec/mode-spec.md) · [运行架构](spec/architecture.md) | 目标行为、数据归属、模块和客户端差异 |
| 3 · 具体实现 | [机制专题](mechanics/README.md) | 分支、技能、召唤、伤害等执行边界与验证方法 |
| 4 · 逐项验收 | [实施清单](checklists/README.md) | B01–B09 批次记录及每个身份、槽位、技能、敌人的勾选依据 |
| 5 · 研究依据 | [数据与证据](research/README.md) · [生成报告](generated/README.md) | 源字段、客户端观察、尚缺证据；自动统计不等于行为完成 |
| 工具与运行 | [开发说明](development/README.md) | 环境、构建、提取、检查、联机与打包 |
| 历史材料 | [归档索引](archive/README.md) | 已被替代的方案、旧审计和阶段记录，不能指导当前实施 |

## 文档维护分工

新增内容放入对应层级并更新该层入口。一个结论只在负责它的文档维护，其余位置链接引用；根目录不再增加交接、Task Plan 或跳转占位文件。

已完成的机制说明仍用于维护代码，保留在 `mechanics/`；只服务旧版本的审计、被合并的文档与旧计划归档。验收记录保留稳定 ID、依据摘要及原有勾选，不因整理而重置或提升完成状态。生成清单和报告须同步修改生成器，防止重建恢复旧路径。

项目 Agent 入口为 [AGENTS.md](../AGENTS.md)。[自动维护任务协议](../assets/task/README.md)仅在明确使用 supervisor 工作流时管理执行状态；[用户收件箱](../assets/todo.md)的勾选由用户验收，不与实施清单混用。
