# 卫戍协议 Web 架构整改设计

> 2026-09-05 决策：停止私服路线，以纯 Web 单机复刻为唯一产品目标。当前 `mode.js`、`engine.js` 和 `index.html` 是迁移源，不是目标架构。

## 1. 当前问题

- `mode.js` 同时负责数据加载、可变状态、运营规则、战斗编排、DOM 生成和输入。
- `engine.js` 同时负责模拟、空间查询、地图、相机、单位、弹道、粒子和拖拽。
- `G`、`B`、`BDATA` 与 `window.__*` 形成隐式双向协议；局部修改容易只更新部分状态。
- 地图、单位与特效先合成整幅位图再裁剪，不适合四战场、大量对象和独立质量降级。
- 现有 smoke 依赖单脚本全局符号，能保护旧行为，但不能继续决定新架构。

## 2. 目标模块

```text
web/src/
  data/         生成数据加载、schema/version 校验、资源目录
  domain/       GameState、命令、领域事件、回合状态机、存档
  rules/        商店、盟约、策略、装备、干员与结算规则
  simulation/   BoardWorld、敌人/干员系统、空间索引、伤害与弹道
  render/       相机、viewport、地图层、单位层、特效层、对象池
  input/        指针/键盘 → 命令，不直接修改状态
  ui/           DOM 组件，只读 view model 并派发命令
  app/          装配、主循环、质量档位、诊断
web/legacy/     迁移期间保留的 mode/engine 兼容代码
web/index.html  唯一运行入口
```

不要求第一步就搬完文件。每次迁移一个完整行为切片，并用适配器维持旧入口，直到消费者归零后再删除旧全局。

## 3. 依赖方向

```text
data → domain → rules → simulation → snapshot → render
                ▲                         └──────→ ui
                └──────── command ← input/ui
```

- `domain/rules/simulation` 不读取 DOM、Canvas、音频或浏览器事件。
- `render/ui` 不修改 `GameState` 或 `BoardWorld`。
- 跨层通信只有 command、domain event 和只读 snapshot。
- 同一局只有一个 `GameState`；四人模式是四个 `BoardWorld`，不是四份页面状态。

### 3.1 已建立的状态边界

`web/src/domain/game-state.js` 是迁移期唯一状态根，当前包含 `catalog`、`session`、`battle` 三个 scope、单调递增 revision、命令注册/派发和领域事件订阅。命令 handler 先返回完整 changes，全部通过 scope 与值校验后才一次提交；handler 抛错或返回非法 change 时 revision 和状态根保持不变，禁止嵌套派发。

旧 `G`、`B`、`BDATA` 仍是现有脚本内部的可变别名，但创建、替换与清空都通过 `legacy/replace-scope` 注册到同一状态根。这个兼容入口只供迁移使用；新模块必须调用 `ArkState.dispatch`，不得新增直接全局写入。后续每迁移一个行为切片，就用具体 command 替代对应旧写入，直到可以删除 legacy adapter。

## 4. 运行循环

```text
requestAnimationFrame
  ├─ 累积时间，最多追赶有限数量的 30Hz simulation ticks
  ├─ 发布 FrameSnapshot
  ├─ 根据 viewport 做可见性裁剪与批量绘制
  └─ 更新发生变化的 DOM UI
```

必须限制单帧追赶次数，标签页恢复或卡顿后不得一次补算无限 tick。模拟随机数来自局种子，禁止热路径直接调用 `Math.random()`。

## 5. 热路径数据结构

- 运营态使用可读的普通对象和 `Map`。
- 敌人、弹道和粒子热数组采用稳定 ID + 紧凑数组/TypedArray；删除使用 free-list 或 swap-remove。
- 索敌和范围伤害使用按地图格划分的空间桶，禁止每名干员每帧扫描所有敌人。
- 粒子与弹道设硬预算并池化；超预算时优先降低装饰粒子，不得丢失真实伤害事件。
- 静态关卡、图集和材质由四块战场共享，不复制纹理。

## 6. 渲染边界

渲染固定分层：背景/地形、地块语义、单位、弹道、粒子、选择反馈、DOM HUD。每层独立裁剪和质量降级；单位头像不能再通过整张地图低分辨率位图获得最终清晰度。

Canvas2D 是当前基线；先实现分层、裁剪、批绘与对象池。若标准压力场景仍超过 `docs/architecture.md` 的预算，再把单位/粒子层替换为 WebGL2，规则和状态层不受影响。

### 6.1 已实现的 Canvas2D 分层

- 地形、地块语义和路线只绘制到静态 scene cache；相机稳定后，其投影结果也缓存为 screen layer。正常帧只用一次 `drawImage` 恢复静态背景，不再为静态层重走地形格与透视分块。动态层仍需透视合成，复测证明它仍是下一阶段必须继续削减的成本。
- 候选物、交互反馈、单位、弹道和粒子留在透明动态 scene layer；进入绘制前按当前地图窗口加 padding 裁剪，模拟状态不受可见性影响。
- 弹道和命中粒子使用 free-list 对象池。弹道全部参与移动与命中结算，超过质量档视觉预算时仅抽样绘制；粒子达到预算后覆盖最早的低优先级装饰粒子。
- `ArkRender` 提供 `high`、`balanced`、`low` 与 `auto`。高档保持 3×离屏和 24×24 透视细分；平衡档为 2×/16×16；低档为 1.25×/12×12，并降低弹道与粒子采样。
- `setRenderQuality(id)` 可在运行时切档，`?quality=high|balanced|low` 可固定调试与回归环境；切档会使静态 scene/screen cache 失效并按新参数重建。

## 7. 迁移顺序

1. 建立可重复性能压力场景，记录当前 p50/p95/p99、对象数与内存趋势。
2. 建立 `GameState`、command/event 与旧 `G` 的适配器。
3. 迁移回合、商店和候选区，先解决单一权威状态。
4. 建立 `BoardWorld` 与空间索引，迁移敌人/干员/伤害系统。
5. 建立分层 renderer 与四 viewport，迁移地图、单位、弹道和粒子。
6. 把 DOM 事件改为命令派发，拆出 UI 组件。
7. 旧 smoke 转为通过公开接口运行；增加固定种子整局测试与浏览器性能回归。

## 8. 地图 / 镜头 / 四战场规格（玩法目标）

这里的多人语义指同一浏览器内模拟和显示四名玩家的战场，不包含网络房间或远程同步。

### 8.1 三段式地图
- **地块 1（上）· 怪物预览**：随机放置下一关敌人；策略阶段通过右上放大镜把镜头移到这里。仅平面两方向平移，无朝向旋转。
- **地块 2（中）· 1–13 关（非 boss）**：单人用左半侧。联机随机两两一组；同组有玩家漏怪后，等所有组员结束会合，把**没漏怪的玩家**按**从左到右顺序**尝试填满 **2 个位置**，让漏掉的怪物以**初始状态**从**最右侧两个红门**出现，穿行**整张图**到**最左侧蓝门**；若同组仅一人没漏怪，则只从左半图出怪。
- **地块 3（下）· 14–15 关 boss 战**：单人仅分到左半侧（视角须含**中央 5 格 boss 区**）；联机随机两两同图、左右随机分配位置、共同面对 boss。

### 8.2 尺寸与显隐
- **单玩家作战视角窗口 = 13 宽 × 7 高**。从候选区往上数，屏幕最多容纳 **7 行**高；随后遇到**一整行全不可部署**的地块，天然把地图切为三段。
- 该 13×7 窗口**居中显示、高度占满屏幕**。
- 最上怪物预览块高度不够：其上方**空出一格虚拟网格**高度，把 **5×7 预览块居中**显示，**无需缩放**。
- `12` 一起显示、`3` 单独显示；显示 12 时镜头移到隐藏 3，显示 3 时隐藏 12。

### 8.3 镜头（替换旧 3D 透视）
- 相机**只做平面平移（无朝向旋转）**；局部(13×7)与全图总览(隐藏上/下两部分)之间有**缩放**过渡。
- 左半视角 / 右半视角的平移矩阵**互为镜像**；另有**全图总览**视角。
- 需替代现有 `project`/`drawWarped`（pitch/roll/yaw）、`computeFit`、`battleBenchRowCount`、开战隐藏候选区等旧镜头逻辑，统一为上述尺寸与平移矩阵。

### 8.4 UI
- **半区切换按钮**：中部靠下、商店正上方；中间显示**所在半区**，左右各一个**箭头**按钮；另有放大镜入口查看预览块。

### 8.5 备注
- 具体三段网格坐标、boss 5 格、红/蓝门全集等需从关卡 `mapData` / 相机数据取得；在拿到前先实现"13×7 纯平移窗口 + 三段分块显隐 + 半区切换 UI"的镜头语义，坐标后补。

- 方法：在 `web/src/**` 逐切片迁移，旧 `mode.js`/`engine.js` 通过适配器保留到消费者归零。
- 必须验证：现有 Web smoke、固定种子整局场景、浏览器视觉回归和标准压力场景。
- 可能传播：`web/*.json` consumer、`web/index.html` 入口和直接相关架构文档。
- 范围外：`server/`、客户端补丁和无关提取器。
