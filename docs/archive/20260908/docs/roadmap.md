# 纯 Web 复刻路线图

> 2026-09-05 起，项目停止官方客户端改造与私服路线。整改前历史保存在 Git 标签 `pre-web-refactor-20260905`。

## Phase 0：方向与安全基线

- [x] 确认纯 Web 单机复刻为唯一产品目标。
- [x] 保存整改前 Git 快照并保护忽略的 OBB、GameData 与导出资源。
- [x] 定义状态、规则、模拟、渲染和 UI 的单向依赖。
- [x] 定义 1080p 与四战场压力场景的性能预算。

## Phase 1：性能基线

- [x] 建立固定种子压力场景和浏览器采样工具。
- [x] 测量当前模拟、整图重绘和透视分块合成，记录短时堆占用与长任务。
- [x] 分别测量单战场与四战场，输出 p50/p95/max。
- [ ] 在分层与池化完成后补一分钟持续压测、GC 和内存趋势。
- [ ] 以数据决定 Canvas2D 优化是否足够，暂不提前迁移 WebGL。

## Phase 2：单一游戏状态

- [ ] 建立 `GameState`、command、domain event 与存档版本。
- [ ] 为旧 `G`、`B`、`BDATA` 建立只读/写适配边界。
- [ ] 迁移回合、商店、候选区、装备和部署动作。
- [ ] 固定随机种子，使相同命令序列得到相同结果。

## Phase 3：战斗模拟热路径

- [ ] 建立每玩家一个 `BoardWorld` 的模型。
- [ ] 使用空间网格完成索敌、大范围伤害和碰撞查询。
- [ ] 使用稳定实体 ID、紧凑数组和对象池管理敌人、弹道与粒子。
- [ ] 建立 30Hz 固定 tick、有限追帧和后台恢复策略。

## Phase 4：分层渲染

- [ ] 拆分地形、语义地块、单位、弹道、粒子和交互反馈层。
- [ ] 相机只管理 viewport/投影，不修改世界状态。
- [ ] 只绘制可见区域和可见实体，共享图集与静态地图资源。
- [ ] 支持四 viewport 同屏与非焦点战场质量降级。
- [ ] 若 Canvas2D 压测不达标，仅迁移单位/粒子层到 WebGL2。

## Phase 5：规则与玩法闭环

- [ ] 移除职业技能模板和临时 Boss 路线等近似实现。
- [ ] 接入策略、技能、天赋、装备、特殊敌人和地图切换。
- [ ] 为每类规则补来源、正例、边界和反例验证。
- [ ] 完成固定种子整局回放测试。

## Phase 6：UI 与视觉还原

- [ ] DOM UI 只读取 view model 并派发命令。
- [ ] 建立地块资源映射、组合规则和统一缺失资源降级。
- [ ] 完成商店、候选区、详情、HUD、音效和视觉回归。
- [ ] 完成 1080p、1440p、高 DPI 和低档质量验收。

## 完成定义

- 单机完整流程可以离线运行并确定性回放。
- 标准压力场景达到 `docs/architecture.md` 的性能预算。
- 规则层不依赖 DOM/Canvas，渲染层不直接修改游戏状态。
- 四战场同屏不会复制静态资源或造成持续内存增长。
- 所有未验证的客户端差异仍明确标记，不以近似实现冒充复刻完成。
