# 工程实现与证据

适用于实现与架构判断；按当前变更选择相关检查，不要求为局部修改调查整个仓库。

## 定位现有能力

声称项目缺少能力、需要新增基础设施或只能采用绕行方案前，检查相关入口、已有抽象与直接调用链。无法确认时标记未知，不把未找到等同于不存在。

当目标、修改点和验证方式已有足够证据时进入实施。后续调查应解决会影响方案或验收的具体未知项。

## 数据来源与行为契约

涉及数据转换、呈现或持久化时，确认来源、转换过程、输出及状态所有权。语义不同的数据即使能生成相似外观，也不能代替任务要求的数据源。

保留用户要求的行为、精度与持久化保证。实现与已验证客户端行为不一致时记录差异；客户端事实与仿真实现约定的区分见 `research-evidence`。用户允许的实现约定不应被升级为未经要求的精确复刻任务。

新增职责具有独立状态或生命周期时考虑独立模块；拆分以完成当前目标为限。

## 完成与验证

选择能证伪错误实现的检查，验证用户要求的实际行为。编译成功只支持语法或类型结论；占位 UI、模拟数据或尚未接通的数据路径不能证明对应真实功能完成。用户要求的原型或测试替身按其约定验收，说明验证范围即可。

修复本次工作引入的问题并验证受影响路径。目标检查与项目要求的检查通过后，仅在新改动、失败或未解决风险需要时扩大或重复测试。

所需数据或外部条件缺失时，完成其余可独立验证的已授权部分，并明确具体缺口；不得自行降低验收要求后宣称完整完成。

报告实际结果及关键验证证据。仅在存在相关限制或未完成项时说明，不强制固定章节。
