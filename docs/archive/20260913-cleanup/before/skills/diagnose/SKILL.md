# Diagnose

## 原则

1. 证据优先: 别人的结论是线索不是事实, 每个判断都回本次真实日志, 源码, 状态重验. 
2. 单变量实验: 每次只改一个变量, 用最小可证伪实验验证假设; 不混改, 不碰运气. 
3. 噪声≠根因: 日志报错未必是故障原因, 修噪声不冒充修根因. 
4. 证据前不动手: 实验前明确操作边界和不可触碰项, 只有边界本身影响用户决策或风险时才显式报告; 优先使用可逆实验, 会产生持久副作用的实验必须先明确恢复策略. 
5. 不提前下结论: "还在跑"≠"已修复", 跨过原失败临界点, 拿到确定信号才算. 

## 流程

1. 建立可证伪假设与操作边界; 只有它们影响用户决策、风险或实验授权时才显式说明. 
2. 取真实现场: 对比"成功那次"与"失败那次". 
3. 定位精确失败点: 结构化输出逐层看, 锁定具体步骤, 退出码, 时间点. 
4. 区分竞争假设：优先取得能定位失败机制的证据。结论仍有歧义时再补充独立来源，不规定证据数量。
5. 假设驱动实验: 先无副作用验证 (重跑/重现) , 再单变量精确实验; 实验失败后恢复到可确认基线, 涉及持久化或外部状态时不假设回滚天然安全. 
6. 持续观察: 等待能判断原故障是否消失的结果；根据操作特性设置超时，不无限轮询，也不凭中间状态宣告修复。
7. 证据足以支持修复时实施，验证原故障及受影响行为；仍未确认的根因标注为假设。
8. 简要报告原因、实际修复和验证结果；只有影响使用或决策的限制需要补充说明。

## 本机工具习惯

- 搜索优先 `rg` / `rg --files`；读取用当前可用工具，PowerShell 可用 `Get-Content -Raw`。
- 读取无 BOM 中文文件时使用 UTF-8；PowerShell 5.1 需显式指定 `-Encoding UTF8`。
- 命令简短单一, 避免一行嵌套多重引号/反引号. 
- 先定位再读, 不盲目递归全目录搜索. 

## 卫戍协议故障特例

- 行为与 `docs/mode-spec.md` 或客户端表现不符时，先用 `research-evidence` 确认证据等级。
- 截图只证明可见布局，不自动证明交互机制、数值或内部状态。
- 已验证客户端事实与实现冲突时，必须明确记录差异，不得以当前代码覆盖研究事实。
- 自动维护中的失败、阻断和恢复均使用 supervisor 当前支持的 `Fail`、`Block`、`Resume`，不得发明额外状态动作。
