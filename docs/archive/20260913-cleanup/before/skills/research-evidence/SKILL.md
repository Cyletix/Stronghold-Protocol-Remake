# Research Evidence

本仓库涉及逆向研究、数据提取与仿真实现。写入 findings、玩法规格或代码依据的客户端行为结论须保留来源和证据等级。工程实现选择与用户要求不等于客户端事实，不因实现成功而升级证据等级。

## 证据等级

### Verified
可由客户端数据(resource/gamedata)、AB 资源、代码、网络行为或可重复实验直接支持。
写入正式 findings / spec 时标注 Verified 及来源；沿用所在条目或章节的明确标记即可，无需逐句重复。此处代码证据指客户端相关实现，不能用本项目仿真代码自证一致性。

### Inferred
有多个迹象支持，但无法直接确认(例如截图观察 + 模型推测)。
必须明确标记为推断(如 `[Inferred]` 或注释)，不得无标记升级为正式行为规格。

### Hypothesis
用于指导下一步研究的假设。
不得作为实现正确性的唯一依据；实现前必须尝试验证或至少标注为假设。

## 升级路径
按证据强度更新等级；直接证据充分时可从 Hypothesis 升至 Verified，不必凑齐中间阶段。

禁止把 `截图观察 → 模型推测 → 直接写进 mode-spec → 再拿 mode-spec 指导代码` 这条链，让推测静默变成「事实」。

## 使用
- 写入 findings/spec：必须标注证据等级。
- 实现客户端已知行为时依据 Verified；Inferred 需标注来源与不确定性。用户明确要求、但原作机制未确认的仿真行为可按项目规格实现，标明这是实现约定；Hypothesis 不得作为已复刻正确的唯一依据。
- 发现「实现与已验证客户端行为不符」：差异必须明确记录(如注释或 findings)，不得静默覆盖事实。
