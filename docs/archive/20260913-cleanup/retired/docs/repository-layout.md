# 仓库结构与文件管理（当前版本）

目标是把“运行链、研究链、历史归档链”严格分离，减少误用。

## 1. 目录职责

| 目录 | 目标用途 | 是否核心 |
|---|---|---|
| `web/` | 浏览器运行前端、素材与页面资源 | 核心 |
| `tools/` | 提取、构建、校验、联机服务脚本 | 核心 |
| `data/` | 本仓库内的 ArknightsGameData 快照（`zh_CN/gamedata`） | 核心 |
| `work/` | 解析中间产物与本地计算缓存 | 辅助（可重建） |
| `assets/` | 任务文档、截图、外部导入素材 | 核心（workflow 与素材） |
| `docs/` | 当前文档入口与证据体系 | 核心 |
| `docs/archive/20260908/` | 历史阶段材料与迁移痕迹，阅读时注明历史性 | 归档 |
| `server/` | 辅助探针与实验服务 | 辅助 |
| `.runtime/` | 本地运行运行时与打包依赖 | 不建议直接编辑 |
| `.agents/` | 自动维护任务体系与工具指令 | 核心 |

`.gitignore` 已将可再生资源（提取产物、缓存、运行时大文件）排除，避免污染提交。

## 2. 文件流与职责边界

- 研究与证据：`docs/*`（当前） 与 `docs/archive/*`（历史）分离。
- 数据导入：`data/` + `tools/extract_*.py/js` + `tools/build_*.js`。
- 运行时链：`web/`（前端）、`tools/room_server.js`（联机服务）、`tools/run_server.py`（调试入口）。
- 任务系统：`assets/task/` 作为状态机入口，`assets/todo.md` 只存收件箱。

## 3. 当前建议清理边界

- `tools/main.py` 属于历史遗留实验入口，当前不应进入联机/运行主链。
- `web/`、`.vscode/`、缓存目录、截图目录保留但不作为代码入口。
- `dist/`、`assets-extracted/`、`work/` 为产物目录，尽量保持可重建。

## 4. 版本和分支约定

- 分支建议沿 `codex/<主题名>` 命名并保持小步推进。
- 合并前至少确认一次 `docs/` 的入口文档已更新，尤其是受影响的数据流/脚本链入口说明。
- 与任务相关的“完成/变更边界”必须在 `assets/task` 任务文件中闭环记录，避免只靠文档修改替代工程验收。

## 5. 何时归档

当脚本或文档只用于历史问题排查、一次性对齐、不可复用的验证时：

1. 保留内容到 `docs/archive/*` 或 `assets/archive/*`；
2. 在现有文档入口新增“历史参考”链接；
3. 在调用路径中标注“仅历史，不应复用”。
