## 怎么读与维护

- `[x] 资料检查` 只表示脚本直接确认该字段/身份/导出候选存在。它不是“天赋或技能已正确实现”。
- 其他 `[ ]` 是行为验收：状态在同一行注明“缺导出 / 旧分类待核 / 专用路径待验收 / 已知缺口”。当前不凭函数名或测试文件名批量勾完成。
- 完成一项后在 Markdown 勾 `[x]`，并在紧接的下一行添加 `  - 记录：实现位置；测试命令与具体断言；原始依据/仍有的近似；日期`。部分完成保持未勾，用同样的记录行写进展。
- 行末隐藏的 `review:... basis:...` 是稳定 ID 和依据摘要。重建保留勾选和记录；源字段、可观测目录或处理器登记变化会重新打开相关项；删除已记录的对象会报错，防止丢进度。共享执行代码改动时须沿影响范围重新核查，脚本不宣称理解代码语义。不要删这些标记。
- 行为记录先区分“源表已确认的规则”和“当前仿真实现/近似”；泛化 smoke 通过不能升级为原版一致。专项源码命中、测试引用只用作定位线索。
- 纯说明整理不改变既有验收；若生成摘要因文案变动而变化，先确认源数据与运行逻辑未变，再保留原稳定ID、勾选和记录。共享文件哈希变化本身不证明所有依赖行为失效，不因此重做无关源码研究。
- 原文中某些技能名字随等级/版本变化，统一以 charId / skillId / chessId 追踪；“未列出召唤物”不证明没有隐藏实体。临时借用另一干员的召唤物数值不能勾选完成。
