# 联机与分享专题

核对日期：2026-09-12。四席大厅、独立运营、自动普通战、联防/Boss共享战场与队友观战已接入房间服务。本文区分本地实现、验收记录和外部连接条件；实现通过不等于原版全部规则已核实。

## 建议与边界

房主自己的Windows电脑可以当游戏服务器：运行项目自带的Node程序，朋友访问它提供的网址。两名熟人测试不要求租云服务器、部署Linux或配置SSH。房主必须保持电脑和程序运行；跨地点仍需让朋友能访问主机，具体选择见[异地连接](#异地连接)。

当前游戏采用主机统一计算、浏览器提交运营操作并读取画面状态。即使EasyTier底层打通P2P，游戏规则仍由房主电脑执行；不是两端各算一局。没有已上线公网入口，也没有跨运营商稳定性结论。

## 发什么给朋友

所有人使用同一个通用包，完整解压后双击 `开始游戏.cmd` 打开原游戏主页。从「卫戍协议」直接进入原四席房间，默认单人在第一席，其余为空席；模式、赛季、难度和地图集中在卡片下方。单人点“开始本局”直接运行本机游戏（不创建服务器房间）。选择多人后，在同一画面创建同盟或输入朋友的分享码；连接完成仍显示同一套四席房间。赛季、难度和地图只在房间内设置，新房间默认「盟约Ⅱ／绝境模拟／Ⅱ·第1关」。启动后先看「开局情报1/2」，再点下一步进入「选择策略2/2」，保留原来的策略排列与展开动画。无需安装GUI、填写IP、网络密钥或第二个房间码。

昵称和头像自动保存到包根目录 `user-config.json`，换端口或关闭程序后重开仍可恢复。115张实际存在的立绘均可选，选择器支持搜索和分页，名片只影响展示。保存采用原子替换，损坏配置回退默认；发行包不携带打包者配置、同盟密钥或席位凭据。修改头像可从大厅“修改昵称 / 头像”回名片面板；等待大厅会同步更新，已开始的对局保留本次名片，新设置供下次使用。

通用包包含完整网页资源，任何接收者都能创建房间。加入者的本机网关从自己的 `web/` 读取页面、脚本、数据、头像和音频，仅联机API经EasyTier转发到房主；文件缺失直接报错，不回退到房主下载。连接前核对双方页面与规则文件指纹，不同版本明确拒绝混用。大厅左上角可回首页结束连接、重新创建或加入；退出席位后首页会清理失效连接。关闭房主启动窗口会丢失内存对局；重开时使用新分享码。短暂网络中断由EasyTier尝试重连。

### 生成通用包

运行开发入口 `tools/Package-Room.cmd`，输出到 `dist/`：

- `Arknights-Game-Universal-Windows-<架构>-<批次>.zip`：所有人使用同一包，启动后选择创建或加入。
- 对应的 `.sha256` 校验文件。

包内带Node.js和EasyTier便携运行时，首次也不必下载依赖。游戏只用Node内置模块，仅保留node.exe及许可证，不复制npm。EasyTier优先使用根目录的 `easytier-windows-x86_64-v2.6.4.zip`，核对官方SHA256后提取核心程序、管理程序和所需DLL；GUI安装器保留但不执行。缺少便携缓存及本地ZIP时才尝试官方下载。

每次创建生成带校验的 `WS1-…` 分享码，含80位随机量；通过不同用途的SHA256派生私有网络名、网络密钥及内部房间标识。包内不预置身份、会话或 `online-room.json`，换房主无需重新打包。分享码具有加入本局的权限，只发给约定的朋友。

实现入口：`room-launcher.js` 提供仅监听127.0.0.1的首页和连接控制，`room-share-code.js` 负责码的校验和派生，`room-online.js` 管理传输；`room-web-client.js` 提供加入者的本地静态服务和API转发白名单，不运行第二套游戏仿真。首页控制API检查Host、Origin及随机请求密钥；网关仅接受本机地址来源，并将合法请求的Host/Origin映射为上游服务。入席凭据经本机页面fragment交给大厅后立即清除，浏览器刷新使用自己的席位凭据恢复。现有局域网API兼容保留。

只复制白名单脚本、运行环境、许可证和必要网页资源，不复制APK/OBB、data、work、研究文档、Git仓库或正在运行的房间。`-NoRuntime`省略Node缓存，会使首次启动可能需要下载；`-LocalOnly`生成原来的局域网包。默认不使用这两个选项。完整操作说明见[联机使用说明](../../联机使用说明.txt)。

### 项目内启动和局域网备用入口

完整项目与通用包均双击唯一入口`开始游戏.cmd`；旧启动别名已归档，不再要求使用第二套入口。既有完整实测范围是Windows x64与PowerShell 5.1；ARM64、macOS/Linux自动启动器及真实手机仍未验收。

`开始游戏.cmd -LocalOnly` 保留传统局域网方式，优先监听 `0.0.0.0:8003`；朋友自行访问启动器打印的房主网卡地址。底层开发命令 `node tools/room_server.js` 仍默认127.0.0.1:8001。

2026-09-18修复启动端口：现场Windows保留范围7944–8043、8044–8143覆盖8003和8100，原启动器只处理`EADDRINUSE`，因此遇到`EACCES`即退出。主页、房间服务及联机端口探测统一使用`tools/lib/listen-port.js`：跳过占用或不可用端口，附近20次尝试未成功则由系统分配可用端口；其它错误仍原样报告。主页由最终HTTP服务器直接绑定，消除先探测释放再绑定的竞争窗口，页面地址、房间链接继续使用实际绑定端口。无需修改Windows保留范围或提升权限。

端口回归入口为`node tools/_launcher_port_smoke.js`；便携包验收`node tools/_room_package_smoke.js <解压目录>`同时覆盖默认主页入口与局域网入口，使用包内Node、无关工作目录和真实HTTP请求，不能以`-CheckOnly`代替实际启动。

### 关闭网页与进程回收

以下是本机启动器的实现约定，不是原版规则。默认双击“开始游戏.cmd”后，首页、模式面板、大厅和战场各自保持一条本机页面连接；最后一页关闭后等待15秒，随后退出席位、关闭EasyTier与本机HTTP服务，启动窗口自然退出。页面刷新、跳转和浏览器后退在宽限内接续，后台页面不依赖JS定时器保活；开着其他游戏页面时不会回收同一启动器。首次启动两分钟都没有页面接入也会退出。房主完整退出会结束内存对局，朋友需等房主重新建房；返回主页、返回大厅不是退出整个程序。

`launcher-window.js`在大型资源之前运行，独立保存仅用于页面保活的临时令牌；`launcher-windows.js`管理本机SSE连接及宽限；`room-launcher.js`校验令牌、Host和确切的本机页面Origin。它不向网页开放任意终止进程的API。`game-process.psm1`把Node及其子进程放入本启动器独占的Windows Job，设置KILL_ON_JOB_CLOSE：即使强制关闭启动窗口，系统也会清理它启动的EasyTier。浏览器由Job外的父启动器打开，避免游戏退出连带关闭浏览器。不会按进程名查杀其他游戏或用户自行启动的EasyTier。旧版已遗留的进程不由新启动器接管。

`-NoBrowser`是显式后台运行入口，不启用页面退出计时；`-LocalOnly`传统手工局域网服务也仍由启动窗口控制。两者通过脚本启动时仍受Windows Job保护。

重复点击建房／加入被当前连接状态拒绝；查找房主最多约两分钟，失败或取消会回收本次进程，之后才允许手动再试。游戏内轮询重试不会重新启动EasyTier；同一实例负责已有连接的恢复。没有无限创建进程或切换新分享码的自动重试循环。

2026-09-11验收：`_launcher_window_smoke.js`以真实隔离EasyTier验证最后一页关闭后的PID退出、双页面、跳转宽限、没有页面计时心跳仍保活、首次未打开页面、连接途中关闭及Origin／令牌拒绝。`_game_process_smoke.js`强制终止专用PowerShell进程，确认其Node及孙进程由系统回收；`_room_share_smoke.js`验证建房／加入／准备／开局与取消流程。

## 异地连接

### 已集成的EasyTier无虚拟网卡方式

使用官方CLI 2.6.4的 `--no-tun` 和端口转发：房主游戏只监听本机127.0.0.1，加入者创建本机网页入口；仅API通过其背后的EasyTier转发通道访问房主，静态文件来自加入者自己的包。无需创建虚拟网卡、安装系统服务或驱动，也不改系统PATH、DNS、防火墙、路由器UPnP。官方无TUN模式和端口转发说明：[no-TUN](https://easytier.cn/en/guide/network/no-root.html)、[端口转发](https://easytier.cn/guide/network/port-forward.html)。Windows安全软件自身的提示仍不能被脚本绕过。

两端使用加密的私有网络，网络密钥不放入进程命令行。管理RPC只绑定回环地址；房主仅放行实际游戏TCP端口，加入者不导出其他本机TCP/UDP服务。测试已确认不能通过组网访问房主另一个本机HTTP端口。加入者通过成员列表自动发现房主实际端口，处理本机端口占用及DHCP地址冲突，不要求手动查IP。

2026-09-10核查发现旧示例的public.easytier.cn、public2.easytier.cn和public.easytier.top在当前网络无法解析。默认改用运营者在[EasyTier社区公开的节点](https://github.com/orgs/EasyTier/discussions/1909)：上海sh.vomiku.com:7910用于发现（运营者不承诺中继），us01.225284.xyz:11010提供备用中继。二者本轮TCP连接通过；关闭P2P后，两个加入者经公网中继访问真实大厅和游戏目录成功。节点是社区服务，没有可用性保证；更换时修改 `tools/room-online.js` 的DEFAULT_PEERS并重新分发通用包。

### 重连与公共节点限制

2026-09-11查阅[官方P2P说明](https://easytier.rs/guide/network/p2p-optimize)及[当前节点运营者说明](https://github.com/orgs/EasyTier/discussions/1909)：自动建立／恢复连接是EasyTier的正常能力，没有查到“正常重连即封禁”的统一规则；各节点是否限流、拒绝连接或停止服务仍由维护者决定，不能保证绝不封禁。上海节点明确不承诺数据中继。关闭全部页面后停止本实例的后台连接，保留已有实例恢复，不通过反复重启来追求连通。当前固定CLI为2.6.4，不直接套用新版本文档中的新增参数。

### 日本与国内连接

此方式可以供两地试用，避免对方安装和配置软件；它不会保证跨境线路的延迟或丢包。实际直连取决于NAT和网络，失败时可经中继；备用中继位于美国可能增加绕行延迟，不能将“连得上”解释为“足够流畅”。目前测试是同一台电脑的多个进程经公网共享节点组网，不是日本与国内两台真实设备的对局验收。

## 当前实现与复现

### 四席同盟大厅（N1）

入口是房间服务的 `/` 或 `/room-lab.html`。四张竖向卡展示干员、昵称、创建者/房主、邀请空位与准备状态；稳定slot为0–3，退出不挪其他人，新成员填空位。房主可在启动前移出成员，退出或席位过期时由剩余成员接任；短暂离线不直接转移房主。

[Verified视觉来源] [00:20三人加空位](../../assets/reference/video-audit-20260910/detail-0020.jpg)、[00:40四人已就绪](../../assets/reference/video-audit-20260910/detail-0040.jpg)。当前干员名片是本地可选立绘；真实好友资料、账号助理、公开匹配和原版销毁倒计时未接。按用户最新入口要求，单人房与只有一名成员的同盟房均可启动，使用本机单人规则；2–4人需全员准备后由房主启动。该人数约定不能由截图推定为原版门槛。

启动前禁止game-enter，启动后禁止新成员加入和再次操作大厅准备。等待成员自动进入游戏；刷新或主动返回已启动大厅时保留“返回本局”，不自动循环跳转。大厅准备和每轮战斗准备分别管理。

### 真实联机运营（N2准备阶段）

房主在统一入口选择赛季、难度和地图，建房后仍可调整，修改配置取消全员准备；启动时按人数冻结单人或同盟源模式，所有成员进入后各选策略，不能再次改配置。单人正式入口在浏览器本机模拟，不创建房间或EasyTier连接；以下独立VM和主机确认说明适用于多人。多人每人独立VM复用mode/engine经济、策略与装备规则，购买、刷新、升级、冻结、出售、部署/交换/撤回、装备、装置、奖励和决策均由主机确认。部署预览和命令校验共用本席位源地形合法格集；装置不能落到已部署干员格。

入口边界：原index主页为唯一主页；room-lab复用既有四席布局，承载单人/多人、赛季、难度、地图与连接；room-start只兼容旧链接并替换历史跳转，不再显示选择页。上一轮将情报和策略合并为一页的三栏实现已按用户纠正撤回；房间配置前移不改变原情报→策略两阶段。缺省地图必须明确取Ⅱ·第1关，不能直接取hard.stageChoices[0]，因为该列表首项是旧赛季地图。自动检查覆盖配置保存失败后恢复真实选项、训练模式加入第二人时禁止启动、单人完整Boss结算、无组网单人启动、返回主页不强制续接和失效会话。真实跨境与手机验收仍不在这些本机测试的结论内。

### 自动战斗与共享战场（N3）

- 所有成员选完策略后开始准备计时；当前待选决策未完成时暂停其准备倒计时。全体存活玩家在线且就绪后自动开战，准备时间耗尽且没有待领选择时自动就绪。
- 普通战每人独立G/B。逻辑步长为1/30游戏秒，卫戍模拟固定2倍速；回合计时按真实秒推进。浏览器仅渲染主机的B和地图快照，不自行攻击、回费、扣血或推进时间，切后台不暂停主机战斗。
- 普通战结果明确后，联防按实际漏怪与存活状态筛选防守者，右侧阵型平移，漏掉的敌人按源地形重新建路。Boss按存活名单两两共享战场，右侧阵型及左右朝向镜像；每组拥有自己的一个Boss生命状态，四人房间的两组之间不共用Boss血条。
- 每组首次造成25%、50%、75%首领伤害时各广播一次动态，重复快照不重复产生事件。玩家可以观看其他现存战场；右侧席位默认镜头包含自己及中央区域。所有本轮战场结束后等待3秒，再统一进入下一轮；异常停止推进并显示主机错误。
- 共享结果归还各玩家，隐藏挑战判定使用同盟当前生命与盟约层数。结算仍基于真实本局记录，未伪造原服务器经验、奖杯或称号；复杂Boss机制和原版阶段时序仍需继续取证，网络接线不证明这些规则全部正确。

实现分工：`room_server.js`负责鉴权与HTTP；`room-game-runtime.js`运行规则、战斗与可恢复内存快照；`room-battle-session.js`管理统一时钟、普通/共享战场、过轮等待和同盟事件；`room-game.js`恢复画面及只读观战。配对和地图边界见[多人战场契约](../spec/architecture.md#多人战场契约)。

### 恢复、缓存与验收边界

大厅每2秒同步；主游戏前台准备阶段约500 ms、战斗约100 ms，后台2秒。`room-presence.js` 在样式和大型脚本之前启动独立轻量心跳，贯穿资源加载、策略选择与完整战场同步；`presence` 接口不等待游戏初始化或战斗命令队列。12秒无心跳标记离线并取消准备，首战前允许恢复，首次实际开战后才采用默认60秒掉线宽限。连接异常通过独立横幅提示；本机请求失败立即锁定运营操作，等待完整主机快照确认恢复。

| 情况 | 当前行为 |
|---|---|
| 开局前有人掉线 | 取消其准备，禁止启动；宽限期内保留席位，恢复后重新准备。 |
| 首战前资源加载、选策略或准备中掉线 | 保留席位并允许恢复；等待超过5分钟显示延迟提示，不自动弃权。房主可取消启动，返回同一大厅重新准备。 |
| 首次实际开战之后掉线 | 暂停全房间推进，显示成员名字与剩余等待时间；宽限内恢复后继续，不补跑暂停时间。 |
| 实际作战期间掉线宽限超时 | 该成员本局弃权，席位保留；回来可只读观战，其他成员继续。共享Boss中已部署阵型自动完成当前战场，弃权者不进入后续轮次。 |
| 网络心跳在线但战场未同步好 | 暂停游戏并等待完整快照；久未恢复时房主可主动中止本局、返回大厅，不把心跳在线误当成可以继续作战。 |
| 首战后全员掉线 | 宽限期结束后本局结束；恢复后可回大厅重新准备。 |
| 正常结局或运行错误 | 大厅显示本局结束，由房主“返回大厅再开一局”；保留成员、头像、分享码，清除上一局运行时和准备状态。 |
| 同房间第二局 | runId递增，旧指令不能进入新局；重新选择策略和准备。 |
| 房主电脑或启动程序关闭 | 连接断开；首页可结束连接并重新组建同盟，内存对局无法从主机重启恢复。 |

这些等待时长和失联处理是当前实现约定，不宣称已复刻原版掉线规则。页面刷新可恢复同一服务上的战斗进度，不重新开战；sessionStorage只保存本次席位与同步元数据，不写入个人离线存档。最多8个游戏运行时，没有主机迁移或磁盘续局。修改规则/目录后需重启服务。

2026-09-10异地反馈暴露的旧版缺陷：加入者全部静态资源经过房主，且大厅跳转后直到大型脚本与initMode初始化完成才恢复心跳，超过12+60秒会被错误弃权。修复分别消除远程资源下载和初始化心跳空档，并将首战前加载等待与已作战掉线区分。`_room_web_client_smoke.js`验证58个页面/数据资源从本地读取、房主静态请求为0，以及慢图片不阻塞presence；不能将该验证扩展成跨境线路永远稳定的结论。

该修复另以真实HTML/HTTP验证90秒脚本加载阻塞、80秒运行时创建阻塞仍保持席位；实际两浏览器通过独立EasyTier网络进入策略、自动完成第一回合，并在第二回合刷新加入者恢复原席位。新版通用包通过无系统Node启动及实际建房/加入检查；针对上一通用包生成53.8 KiB覆盖更新，隔离副本应用后5269个发行文件与新版逐一哈希一致，个人配置保留。双方需关闭旧启动程序、完成同版更新，再创建新同盟；旧版已弃权对局不能靠刷新恢复。

全员离线或弃权且本局结束后保存公开终局快照并释放VM；恢复仍可查看终局，不能重新操作旧局。`_room_lifecycle_smoke.js`已验证另一房能立即复用运行容量、原席位恢复终局及原同盟重开。浏览器后退恢复旧游戏页会重新同步runId与完整状态；连续三局的旧点击、旧指令隔离由`_room_game_client_smoke.js`覆盖。
