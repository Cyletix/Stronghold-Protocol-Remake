## 数量限制的回答

- **Verified（字段）**：act1、act2 的 `constData.storeCntMax` 均为6。字段所属对象没有说明“每名干员副本库存”，也没有阶数对应容量表。当前不能用它证明六张卡池。
- **Verified（字段与现有消费）**：`maxBattleChessCnt=8` 是部署数量配置，不能用来证明八张同名卡。
- **未确认**：共享卡池的每阶/每名容量，个人或房间共享，商店展示是否占库存，冻结/出售/合成/赠送如何扣还，回合切换是否重置。没有补录确定数字，没有加猜测上限。
- 2026-09-09的核查范围仅包括两赛季活动对象、全局autoChessData字段和定向字符串；当时找到的removeChessPoolChar/setChessPoolAssist/setChessPoolDeploy/setChessPoolDiyChar名称只能定位相关操作，不能证明库存容量。现在已可沿[客户端逻辑流水线](../research/client-logic-pipeline.md)读取配置、metadata映射和原生调用；此前字符串未命中不再作为“APP没有实现可读”的结论。
- 社区搜索发现[B站共享卡池实测视频](https://www.bilibili.com/video/BV1JWy3BkEpt/)，搜索摘要提及普通占1、精锐占3；正文抓取返回412，未核验实验过程与对应版本，不作为Verified或实现依据。
