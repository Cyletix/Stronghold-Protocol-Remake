## 2026-09-15 固定生命回复属性

角峰 S1 `skchr_yak_1` 的生命上限增益与每秒固定回复已接入共用 `ClientProgram`。源 `hp_recovery_per_sec` 不再落入未执行的旧治疗分类；按实际生效时间回复，跨越到期点时只计算结束前的部分，保存恢复沿独立时间游标继续，不能重复回血。技能结束/死亡移除程序，生命上限与当前生命比例沿已有属性生命周期恢复。

**Verified（源字段）**：`jp-36.7.22-client-logic` 的 `CastSkill` / `ActiveBuffAbility` 图及 CN `skill_table.json#skchr_yak_1` 十级黑板，给出最大生命修正与属性13的固定回复值。[生成器](../../tools/build_client_programs.py)向父编译器声明 Web 实际支持的属性集合；父侧默认仍不接生命回复，避免一个消费者已实现就让其他消费者误报支持。Web现为29个技能ID、20个程序、275份等级，这些是绑定数，不能当作完整技能完成数。公共阻挡数算子也已贯通，但芳汀 S1 的其他模式/二连击仍有缺口，未因属性字段可读而导入整个技能。

**实现与限制**：回复使用生命回复路径，保留禁回复、上限和死亡限制，眩晕不误停生命回复；真实原生事件帧、完整天赋/模组以及不同回复修正的组合顺序继续待核。[属性能力检查](../../tools/test_program_attribute_capabilities.py)有3项来源/拒绝断言；[回复运行检查](../../tools/_program_recovery_smoke.js)核10级实际回血、末帧比例、同帧去重、控制/禁回复/封顶/死亡、公共阻挡消费者和主机恢复。`_client_programs_smoke.js` 的888个既有及新增实例通过。本批仅记录角峰 S1 限定主体，不勾完整技能或整人。

## 属性与传播

[attributes.js](../../web/src/simulation/attributes.js) 保存常驻天赋前的攻击/防御基础，以及静态攻速。[rules.js](../../web/mode/rules.js) 将已登记的普通常驻增益相加；[engine.js](../../web/engine.js) 把持续技能的百分比加在同一基础上，攻速统一计算。普通增益、当次攻击增加值、鼓舞与伤害倍率分别处理。

`resolveBoard → boardView → startBattle` 现在传递 `attributeBase / basicAttack / combatTalents`。此前布阵对象遗漏后两项，实际战斗可能退回最低阶段的特性或失去天赋；测试改走这一完整路径，并另确认雪猎携带8发弹仓和天赋候选。盟约事件重算基础时保留正在生效的技能，结束后回到重算后的基础，避免重复扣除。

**[Simulation：保留边界]** 当前装备/盟约的旧倍率先算入模式基础；本批没有证明它们全部属于同一客户端修正层。生命值、临时固定值与负面修正类别仍需单独核查。旧 `atk/def < 1` 暂按独立最终倍率保留，但原版部分减益实际属于普通百分比减法，不能据此宣布减益全对。技能动作前后摇、攻速改变时已有冷却的即时折算，以及所有天赋/模组条件不是这批完成范围。

属性规则版本参与存档目录指纹。明确兼容的上一版休整库存重新绑定新属性，未知/旧地形目录仍拒绝；正在进行的异版本主机战斗快照不迁移。
