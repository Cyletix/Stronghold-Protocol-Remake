# 四槽甄选编队

2026-09-13。主页点「编队」，或四席房间点「调整甄选」；V 阶两名、VI 阶两名，在同一窗口选择干员、携带技能和精锐模组。按赛季记在本机浏览器，未填槽位不入池。入门协议不启用。开始后仍走原来的「本局情报 → 选择策略」，没有新增强制步骤。

选中干员加入本人商店与按阶数/盟约抽取的奖励池，并非直接免费送到候选区；沿用当前库存、购买、三合一、装备与部署规则。单人从本地读取，联机由各玩家提交自己的选择，主机校验后锁入 session。保存恢复、观战和重连使用该局的选择；此后修改本机编队不改变旧局。

## 来源与规则

**Verified 源字段**：两季 `activity_table.json` 的 `diyChessDict` 均有 `chess_char_5_diy1_a`、`5_diy2_a`、`6_diy1_a`、`6_diy2_a` 四槽，均要求 `TIER_6`；阶数取 `charShopChessDatas.chessLevel`，精锐身份及养成取 `charChessDataDict`。这里的 V / VI 是棋子阶数，不能理解为五星/六星各两名。

**Inferred，采纳 PRTS 规则**：甄选六星排除当季预置干员；自持有身份不能重复。按实际势力和隐藏势力匹配一个或多个核心盟约，未匹配才使用「协防干员」，且没有卫戍专属特质。因此四名甄选干员不一定都是协防。来源：[PRTS 玩法说明](https://prts.wiki/w/卫戍协议)、[盟约记录](https://prts.wiki/w/卫戍协议：盟约/PRTS盟约记录)、[盟约下半记录](https://prts.wiki/w/卫戍协议：盟约_下半/PRTS盟约记录)。本地 `mainPower/subPower`、全局 `bondInfoDict.powerIdList` 和当季盟约目录提供匹配字段；仿真实现本身不作为原版证据。

| 项目 | 盟约 | 盟约Ⅱ |
|---|---|---|
| 当前离线名册中的可选非固定六星 | 90 名 | 77 名 |
| 普通养成 | 精二 1 级、技能 4、无模组 | 相同 |
| 精锐养成 | 精二 60 级、技能 7 | 相同 |
| V / VI 精锐模组等级 | 1 / 2 | 1 / 3 |
| 协防激活人数 | 3 | 2 |
| 协防生效后减伤 | 全部干员物理/法术受伤 -20% | 相同 |
| 生效后造成伤害 | 全部干员 120%，精锐 140% | 仅协防干员 120%，精锐协防 140% |

养成、模组等级和协防参数为 Verified 字段；两季伤害受益对象按各自源说明解释。修正原来的攻击力乘算为命中时最终伤害乘算，避免先放大攻击力再减防导致倍率失真。多核心归属均可计人数并获取对应已有盟约加成。

当前离线资料库没有账号登录/所有权服务，可选范围是已导出、可获得的六星，排除当季固定、隐藏和替补身份；数量表示本地数据范围，不能当作原活动开放当天的可用人数。首次选择继承本机携带技能与潜能；可在甄选窗口改技能和模组。技能的 4/7 级由普通/精锐源槽位决定，不随资料库专精设置升到 10 级。

## 实现与验证边界

- `tools/build_diy_roster.js` 从源表生成 `web/diy_roster.json`，保留源 SHA256、排除名单、完整资格及主/隐藏势力、模块属性与技能身份；`--check` 检查漂移。
- `web/src/rules/diy-roster.js` 由浏览器与主机共用，严格校验槽位、六星资格、重复身份、技能、模组和潜能；不接受注入攻击数值。`rules.js` 以「赛季＋四槽选择」缓存名册，各个源 chessId 保留。
- `tools/_diy_roster_smoke.js` 核对 668 个可选身份×槽位组合的源映射；两季四槽各走实际商店抽取、购买、合成、禁用、技能与养成；验证协防减防后伤害及季节差异、本机配置改变后旧存档仍保持编队、两名主机玩家使用同一干员但不同阶数/技能的签名恢复、共享场地切到队友归属后不借用房主默认技能。`_room_game_server_smoke.js` 通过真实 HTTP 验证各席位提交。
- 新字段 `G.diySelections` 保存该局归属，不依靠账号后来选择重建。旧休整存档精确目录迁移保持空甄选；旧版实时房间不混跑，游戏版本为 `room-game-20260913.4`。

实际浏览器在 1440×900、1280×720、390×844 检查主页与房间入口、换列与遮挡、技能/模组跨页面保留和重复身份排除；房间全局按钮规则已隔离，结束后关闭测试页面。

**仍未完成**：原型干员选择（含 V 阶四星原型、跨阶可重复的模板身份）、好友助战/真实账号拥有及模组解锁验证。它们需要保留不同模板身份，不能用普通 charId 复制凑数。这一批完成用户指定的四名非固定六星路径，不勾 DIY 总项和 B01 整项。

所选角色继续使用各自当前执行器；**能入池不等于天赋、三个技能、召唤物和模组机制均已完成**。例如可露希尔现在可经甄选正式加入，先前战术家专项的有限机制覆盖不因此扩大。逐人差异仍见[实施总表](../checklists/README.md)与[资料库逐人清单](../checklists/library-checklist.md)，甄选逐槽验收见[槽位清单](../checklists/mode-slot-checklist.md)。未打包。
