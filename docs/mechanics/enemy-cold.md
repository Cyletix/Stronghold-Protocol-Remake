# 敌方寒冷与冻结

更新：2026-09-12。本批只处理冰爆源石虫、雪怪小队凿冰人、雪怪小队破冰者。逐项完成状态仍以[敌人清单](../checklists/enemy-checklist.md#enemy_1067_snslime)为准，不把公共状态接入当作所有冰系敌人或干员已经完成。

## 当前执行与边界

- 冰爆虫真正死亡时生成独立延时事件。复活不触发；漏怪不触发；死亡时沉默不生成。爆炸按当时位置和死亡时攻击力计算，死者移除后仍结算，最后一只敌人死亡也等待它。
- 爆炸对圆内已部署干员及召唤物逐个扣防御、检查闪避、施加寒冷；命中区包含浮点误差容限内的圆边界。不同玩家的单位同样受击，不把高台部署类型误认成飞行。
- 敌方寒冷再次施加时转冻结；已冻结时再次施加会延长。攻速加算不叠加；时间到期恢复。冻结停止攻击/技能，保留地面阻挡。召唤物同样停止攻击。
- 真正阵亡、召唤物寿命结束或随拥有者移除、重新部署时清掉状态；流明既有的冻结清除路径可清除此冻结。联机快照保留寒冷、冻结和死亡延时事件，不依赖死亡敌人的对象引用。
- 凿冰人和破冰者的旧常驻攻击加成已排除，仅冻结目标获得源倍率；普通/寒冷/已解冻目标不增伤。不可沉默的条件增伤不会被沉默关闭。
- 简易表现包含爆炸前的范围圈、冰爆散射、寒冷/冻结名称与剩余秒数。范围圈与实际受击使用同一半径；这不是原版骨骼或粒子动画。

**仍未完成**：冰系其他敌人的链式技能、所有干员的沉默/抵抗/免疫来源及完整异常 Buff 叠加系统。执行器接受 `silenceUntil`、`silenced`、`coldImmune`、`frozenImmune`、`statusResistance`（0–1时长减免）等状态输入，并有边界测试；这不代表每个技能都已能正确产生这些输入。冻免/抵抗来源在持续状态中动态变化的完整 Buff 语义尚未实现。友方施加的寒冷配对、减法抗另属技能专项，本批不混入敌方寒冷。冰爆虫的完整能力条目因此保留未勾，仅黑板两键子项完成。

**敌群接入与独立边界**：三类特训选择、逐轮计划和六模板替换已运行；数量、属性加权强度与间隔换算有[原生依据](../research/enemy-replacement-native.md)。这些敌人按源候选池与该局计划入场，不能为展示能力额外硬塞进波次。token/extraEnemy、原版随机序列与服务器覆盖仍待核，冰系能力验收也不代表整场平衡完成。

## 验证

`node tools/_enemy_cold_smoke.js` 使用实际源定义、现有每份关卡覆写、浏览器 VM 和房主 VM，覆盖：

- 三个 ID 的逐项黑板与关卡优先级；冻结前后实际近战命中和防御计算。
- 延时、真死亡/复活/漏怪/沉默、重复触发、独立伤害快照、最后一敌结算等待、对象池复用。
- 圆形边界/范围外、闪避、飞行/未部署排除、召唤物与两个玩家受击。
- 寒冷/冻结/到期、已有攻速加成、冻免/冷免/抵抗输入、死亡及再部署清理。
- Canvas范围和文字绘制调用；主机鉴权快照恢复后的伤害、状态、计时、随机和特效一致。

此为实现回归验证，不能代替原客户端对照。完整回归入口仍为 `node tools/check_game.js`；本轮不打包。
