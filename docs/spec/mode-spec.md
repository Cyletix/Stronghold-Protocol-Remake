## 核心循环

[原生公式／本地执行已接，2026-09-14] 通过完整源图与本地黑板绑定的28个技能ID统一执行Buff程序：生命、攻击、防御、法抗、攻速与基础间隔，按加法→普通倍率→最终加法→最终倍率结算。原生生命上限变化保留当前生命比例；Web同时保留其他机制独立提供的生命增量。逐Buff到期、施放/结束/死亡、真实伤害/面板与鉴权恢复已验证；精确协程帧、受保护的detach调度、未解释talent参数与跨版本一致性仍未完成，见[程序接入与证据](../research/client-program-integration.md)。这只覆盖限定技能主体，不扩展招募池或宣称完整干员已实现。

准备阶段获得资金，采购与刷新、升级调度中心、部署与装备；开战后自动战斗；结算进入下一轮，最终处理配置的领袖战与两屏结算。源模式已移除虚构敌方总血通关条件。单人由浏览器本地运行，多人由房间服务驱动；逐轮敌群与六模板数量/间隔换算已接，原版随机序列、特殊援军及复杂敌方技能仍有缺口。同盟共享战场的结果回写已接，原版完整全队统计、经验/奖杯/称号结算仍缺。

同名合成按源 `upgradeNum`，通常三合一，风丸的特质为两张合成；产生精锐并触发晋升调配特许。装备最多两件随合成保留，多余返候选库存；临时奖励按队列恢复商店。完整原型、好友助战、特殊同名组替代需专门核对。

[用户明确规则] 冻结商店跨回合保留已有商品，空位按本局商店等级补齐，保留商品的价格、属性和顺序；新增商品填入现有右对齐布局的左侧空位。满栏不重抽，策略额外商品不裁掉；补位不作为手动刷新，不扣刷新费或消耗免费刷新次数。沿用冻结保护一次过轮、随后自动解冻的行为。晋级奖励先恢复原商店再处理过轮。验证见 `tools/_frozen_shop_refill_smoke.js`。

## 其余规则的验收边界

技能时序（本地实现约定，字段来源为Verified源表skill_table.levels[].spData/duration/rangeId）：普通/精锐使用各自技能等级的初始SP、消耗、持续与格范围，不另行截断。常规时间回复按increment，攻击/受击分别在普攻发出/实际受击事件加1；一份充能释放一次，持续期间锁定SP并禁止重叠释放，结束或阵亡恢复原范围及临时属性。原手动技能在本模式自动施放；无有效目标时保留充能，负duration按无限持续处理。模拟测试验证本项目行为，不证明所有客户端触发细节。

弹药和特殊回复仍保留明确标记的近似；已接入的下次攻击强化、多段/多目标、持续区域及[限定浮游主体](../mechanics/funnel.md)由专用执行器处理，其余部分仍沿旧分类执行。旧分类是待替换的实现缺口，不能作为新增技能的证据入口；后续按真实prefab绑定、控制器/模式、顺序事件和原生公共方法成批接入。逐项边界见[攻击机制](../mechanics/operator-mechanics.md)，不能仅凭时序或分类命中率宣称所有技能还原。2026-09-12 将医疗治疗、吟游者持续回复及职业分支条件从通用对敌普攻中分离；[基础行动专题](../mechanics/basic-actions.md)集中记录源数据、边界、当前实现及尚未完成的个体技能。此前“医疗、吟游者攻击怪物”是执行器缺失，不是原版规则。

[2026-09-14 更正；Verified：JP 36.7.22原生默认分支与分别注明的CN字段] 活动表 `autoChessData.constData` 给出8个templateEnemy字段与`specialEnemyNum=3`；已从`RandomEnemyGenerater`的原生方法读取类型排期、按前后半/禁用/权重选池、关联普通与精英随从，以及六类普通/精英/特殊空地模板换算。当前CN配置通常为三个类型各3轮、默认类型6轮，共15轮；这是该CN配置值，不是JP代码硬编码。强度为四属性乘各自factor后按float32顺序相加，预算为`P × count / enemyBattleEffectivenessFactor`，新数量由预算除以新单位强度、银行家舍入并限幅；间隔保持`旧count × 旧interval`。关卡属性覆写优先，数量fallback与实际作战专用覆写分别读取，不能把factor乘作生命/攻击加成。方法地址、源SHA和异常分支见[原生证据](../research/enemy-replacement-native.md)。
